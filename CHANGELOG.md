# Changelog

One line per change, written by hand, citing its pull request. Every number is measured.

## Unreleased

- style: `cargo fmt` over the whole tree; the commit is in `.git-blame-ignore-revs` (#?).
- `TESTING.md` (tiers and oracles), this changelog, and `tools/check_style.py` vendored.
- ir: Testbench.dut removed; old JSON carrying it still loads (#13).
- python: YieldSummary.failed and the add_spectre_montecarlo alias removed; use add_spectre_monte_carlo (#13).
- backend: Dialect replaces BackendKind (backend::parse, backend::RUNNABLE, Dialect::run); backend aliases in one table, lint treats vacask-shared as VACASK (#13).
- codegen: Laplace H(s) constants scaled exactly by a decimal shift (#13).
- internal: one walker each for identifiers, expressions and parameters; one table for the 24 waveform-source methods; one analysis suite for ngspice and ESPice (#13).
- nix: `.#testing` builds ESPice from source (OpenFAT/ESPice `5f0b8fd`) and pins the spice-bench suite (6,050 decks) and the Xyce, LTspice, HSPICE and VACASK corpora by content hash (#14).
- tests: a missing simulator, corpus or unbuilt extension fails instead of skipping; 12 ESPice Python tests and 15 Rust tests that skipped in CI now run (#14).
- ci: a nightly tier (`nightly.yaml`) runs the import suite over the corpora, behind the `corpus` feature; the merge tier leaves it out (20 min of a 4-vCPU runner) (#14).
- tests: spice-bench decks ngspice-45 cannot run are named known failures (469 listed, 28 quarantined past the CPU budget); a CPU-limit kill is now reported as a timeout (#14).
- backend: `select` routes on the `Analysis` itself, not a kind string; one predicate (`runs`) for selection and `check_backend`, with a compile-time check that every feature bit has its issue row (#15, audit 30, 41, 42).
- ir: a frequency sweep's spacing is `Sweep` (dec, oct, lin, log), held in `FreqSweep` and the SpectreRF steady state in `PssBase`, both flattened so IR JSON is byte-identical; `AcSweepParams` is now `FreqSweep`. A bad sweep name is a `ValueError` at the Python call and a load error in JSON, where it used to reach the deck (#15, audit 40).
- result: `RawData::backend_hint` is an `Option<Dialect>` (was a string, empty for ngspice) and `VarInfo::var_type` a `VarType`; `parse_measures` takes the `Option<Dialect>`. One `normalize::canonical` pass returns a name's canonical form and whether it is a current (was `normalize_var_name` plus `is_current_name`, two lowercasings each). `Results::column` allocates only for a name with capitals, `RawData::re`/`Results::get`/`axis` borrow a real column, and a Python result column is built into the list straight from it; Python sees the same lists (#15, audit 43, 44).
- codegen: an ngspice deck with a `.meas` or `.four` (from the testbench, or a raw or extra line, `+` continuations included) is written with its first ac/tran/dc in a `.control` block, each `.four` as a `fourier` command (the old rewrite kept only the first); the backend no longer re-parses the deck to move it there and only appends the `write`. A deck handed to the ngspice backend with a `.meas` or `.four` and no `.control` block that runs it is refused with an error naming the card, where it used to be rewritten or, with no ac, tran or dc to move, run with those results silently dropped (#15, audit 38). The ngspice run path compares first words as `&str`, with no `String` per line (#15, audit 45).
- codegen: ngspice, LTspice, HSPICE, Xyce, ESPice, Spectre and VACASK decks are written into one `String` (`write!`), cards and blocks appending to it instead of each building a `String` or a `Vec<String>` to join; Spectre escapes and VACASK quotes each name as it is written, so `netlist()` no longer clones the IR. Every deck the two test suites emit, in every dialect, and the same IRs with every name renamed to need escaping, are byte-identical before and after (9378 decks). 40000-element deck, release, best of 15: ngspice 28.2 to 17.6 ms, Spectre 63.7 to 44.7 ms, VACASK 49.5 to 26.1 ms (#15, audit 46, 47).
- tests: the import suite runs a `.meas` deck once from a `.control` block ending in `write`, as the ngspice backend does, and counts analyses inside the block; its old `-r` reference turned `.meas` off, which stopped `.option autostop` decks at t = 0 (#15).

- codegen, backend: an ESPice deck writes a Laplace source as ESPice's own `E/G … LAPLACE` card instead of an XSPICE `s_xfer` element ESPice cannot read, and ESPice is offered for Laplace decks; real `espice` reproduces the closed-form single-pole, Butterworth and current-output responses, and carries the DC gain into `.op` (#?).
- ir, codegen, python: PWL takes `repeat`/`delay` (ngspice `r=`/`td=`; Python `repeat_time=`, `delay_time=`), written for ngspice voltage sources and ESPice and refused by every other dialect and by ngspice current sources; JSON without them loads and writes back byte for byte. Real ngspice repeats the triangle two periods on to 1e-9 V (python-api-gaps §3 F) (#?).
- ir, import, codegen, python: TRNOISE and TRRANDOM sources (`IrWaveform::TrNoise`, `TrRandom` with a closed `RandomKind`, its TYPE number in JSON), lowered from ngspice decks, written for ngspice and refused by every other dialect, ESPice included (it refuses the cards); Python `TransientNoise*Source` and `Random*Source` on `Subcircuit` and `Testbench`. Both add to the DC value, so a card with none writes back with DC 0. Real ngspice: white TRNOISE has sample std within 5 standard errors of NA (N = 4000), uniform TRRANDOM stays in range with its mean within 5 standard errors (ir-gaps §3 #8) (#?).
- ir, codegen, python: `.pss` takes ngspice's `sc_iter`, `steady_coeff` and `uic` (Spectre refuses them), and a voltage source an RF `port` (`portnum n z0 x`; Python `V(..., portnum=, z0=)`, `pss(..., sc_iter=, steady_coeff=, uic=)`), written for ngspice and ESPice and refused elsewhere; JSON without them writes back byte for byte. Real ngspice runs `.sp` on a matched 6 dB T pad: S11 = S22 = 0, S21 = S12 = 0.5 to 1e-9. ngspice-45 here has no `.pss`, so its card is checked against the manual's example (ir-gaps §3 #9) (#?).
- codegen: Spectre writes coupling, VCVS/CCCS gain, gm, rm and transmission-line z0/td through its one number formatter (`td=1n`, was `td=0.000000001`); the one golden that held the old spelling now holds the new, and no other golden changed (#?).
- ir: `StepParam.sweep_type` is an `Option<Sweep>`, `PoleZero.tf_type`/`pz_type` are `PzTransfer`/`PzKind`, and `SpectreSweep`/`SpectreMonteCarlo.inner_type` is `SpectreAnalysis`: closed keyword sets parsed once where text enters (JSON load, the importer, the Python call, which raises `ValueError`), JSON byte-identical for every value the string fields held. A VACASK `.step` with a log sweep is refused, where it ran as a linear step (audit 40) (#?).
- python: `Testbench` stimulus (`V`, `I`, `R`, `C`, every waveform source) reads node `gnd` as `0`, as `Circuit` does; it used to reach the deck as a floating node named `gnd` (#?).
- python: `spicerack.testbenches` exports `ac_gain_db` and the other AC extractors the skill documents (`crossings`, `ac_passband_db`, `ac_bandwidth_hz`, `ac_unity_gain_hz`, `ac_phase_margin_deg`) (#?).
- python: `CircuitSimulator.spectre_monte_carlo`, the spelling `Testbench.add_spectre_monte_carlo` uses; `spectre_montecarlo` stays as an alias that warns `DeprecationWarning` (#?).
- skills: the backend names list `vacask-shared`; a test checks the skill names every name the module accepts (#?).
- codegen, backend, simulation: an ngspice deck with a `.meas` or `.four` runs every analysis from its `.control` block, in card order, and the backend writes every plot of the run (`set appendwrite`, one `write` per plot in `$plots`); before, only the first ac/tran/dc ran there and the other analyses' plots never reached the raw file. `Dialect::run_all` and `simulation::run_all` return every plot; `run` still returns the first. Real ngspice on `.op` + `.tran` + `.meas`: v(out) = 1 V to 1e-12, v(a) is the 1 kHz sine to 1e-9, `vmax` within 5e-6 of 1 (#?).
- backend: VACASK `run_all` returns every analysis's plot, reading each declared analysis's raw file in deck order (it read only the last one), and a declared analysis that wrote no raw file is an error naming it; `Dialect::run` on a VACASK deck is now the first analysis's plot, as on every other backend. Real VACASK on op + dc + tran of a divider: out = 1.5 V, the swept 0, 0.5, 1 V and 1.5 V at t = 1 ms, each to 1e-9 (#?).
- simulation, python: `Testbench.run()` runs every queued analysis (`add_*`) as one deck and returns one result per analysis in queue order, typed as its immediate twin's (`None` for `add_fourier`); `simulation::run_each` matches each analysis to its plot by name, since ngspice runs a deck's analyses in its own order (ac, dc, op, tran, tf, noise, sens), not the deck's. Before, Python had no way to run the queue: each analysis method ran a copy holding only its own. Real ngspice, ESPice and VACASK on a step-driven RC queued tran, op, ac: op 1.5 V and 0 V to 1e-9, tran 1 - exp(-t/0.5 ms) to 2e-3, |H| = 1/|2 + jωRC| to 1e-6; with a `.meas`, the `.control` path too (#?).
- import: an ngspice deck's PWL `r=`/`td=` (either spelling, `=` or a blank), RF port `portnum n z0 x` (`portnum=n`; z0 50 by default) and `.sp dec|oct|lin n f1 f2` lower into the IR (`Pwl.repeat`/`delay`, `VoltageSource.port`, `Analysis::SPar`) where the whole card was kept raw; an `r=` off a PWL, a port on an I source, a z0 expression and `.sp`'s `donoise` flag stay raw. Real ngspice: three repeating/delayed PWLs over 7 ms and a two-port T pad's `.op` and `.sp` give every vector equal to 1e-12 from the original deck and from the deck written back (#?).
- import, codegen: a Spectre PWL's `delay=` lowers into `Pwl.delay` (it was dropped without a word), and `pwlperiod=` into `repeat` 0 where it repeats exactly as ngspice's `r=0` (`IrWaveform::spectre_pwl_period`: points from 0, last value equal to the first, last segment at least the default `twidth`); any other `pwlperiod`, a `twidth`, and a nonzero `delay` on an FM sine or an exp (no IR field) keep the card raw, where the delay was dropped too. Spectre writes `delay=` and that exact `pwlperiod=` back and refuses any other repeat. Real ngspice runs the imported deck as Spectre Reference 5.0 says (`vsource` #4, #17, #18, p.686) to 1e-9 V over 7 ms (#?).
- schema: `circuit-ir.schema.json` matches the IR it describes: waveform parameters and PWL points are `IrNum` (a number or an expression string; they were numbers only), R/C/L take `model`, `Subcircuit.verilog_blocks`, `Instance.at`, `ModelLibrary.setup_includes`, the top-level `raw_dialect`, `globals` and `functions`, BJT/MOSFET `extra_nodes` (and a null MOSFET `nb`) and the `Poly` component, all absent before. A test validates every IR the IR tests build, the example and three imported decks against it with a 2020-12 checker for the keywords the schema uses; on the old schema the three tests that run it fail with 20, 16 and 4 errors (#?).
- nix: PDKs pinned by content hash; the testing shell no longer pip-installs ciel or fetches over the network (audit #36, #37) (#16).
- backend: ngspice runs with `-n`, so a `./.spiceinit` or `~/.spiceinit` no longer changes a result; `Testbench.ngbehavior` sets ngspice's compatibility mode as `-D ngbehavior=<mode>`, and a mode ngspice rejects fails the run (#16).
- examples: 20 and 21 simulate sky130 (an `X` FET, `ngbehavior="hsa"`) and gf180mcu (`design.ngspice` as a setup include) on every run and fail on a missing PDK; the tests check V(vout) against goldens at 1e-3 and ESPice against ngspice on sky130 (#16).
- tests: the sky130 blocks in `docs/models.md` run in `test_docs.py` (55 s under load); `ngspice_round_trip_keeps_the_op` fails without ngspice instead of skipping (#16).
